# インテリジェンス substrate（事実ベース推論基盤）

> 状態：**基盤の骨格（v0）**。`run_daily` には未接続＝現サイトの表示は不変。
> 目的：記者・要約・まとめ・タスキングが乗る前に、**事実から確度を積み上げる土台**を確定する。

## 0. 設計原理：モデルは提案、コードが判定

本企画の既存原則（`pipeline/core.py` の「LLM/翻訳は提案であって verdict に非ず」「決定論・乱数なし」
NFR-8 / INV-R2）を推論層に昇格させる。

```
LLM（提案）              コード（判定・決定論）            ビュー
──────────              ────────────────────            ──────
事実候補の抽出       →   独立性・矛盾・確度の計算       →   記者 / 要約 / まとめ
主張リンクの提案     →   admission（裏付けなき物を弾く）
導出の下書き         →   確度伝播（証拠が許す上限を超えない）
```

**言語処理（抽出・文章化）はモデル、推論の確度と採否はコード。** これにより非捏造（INV-R2）と
確度評価を構造的に両立する。確度はモデルに「感じさせる」のではなく、証拠から**計算する**。

## 1. なぜ「公開」が最重要制約か

情報収集の方法論は OSINT／競合インテリジェンス（CI）として確立済み（発明しない・載せる）。
諜報との唯一の差は **得た情報を公開する** こと。公開するからこそ各主張は：

1. **合法に取得した公開情報**であること（既存 `compliance.py` / NFR-4＝ToS・robots・引用範囲）
2. **確度ラベルと出典つきで反証可能**であること（誤報・名誉毀損を避ける）
3. 株式は**開示ベースの持分異動**（取得・売却＝大量保有報告書/13D/Form 4 等）に限る。非公開重要情報は対象外。

## 2. データモデル（document 中心 → claim/evidence 中心）

最小単位を「1ソース→1記事」から **主張・事象** に変える。これが基盤の本体。

```
Entity（調査対象）
  ├─ Signal Channel: disclosure（法定開示：持分異動・8-K/13D）  ─┐  最高信頼度(A)
  ├─ Signal Channel: supply_chain（取引先・納品先）              ├─→ Fact（実span・合法・信頼度）
  ├─ Signal Channel: energy（使用電力量）                        ┤        │
  ├─ Signal Channel: hiring / press / forum …                   ┘        ▼
  └─ （タスキング層が掘る順を決める）                          Claim＝仮説（支持/矛盾）
                                                                    │ 独立性・矛盾・確度伝播（コード）
                                                                    ▼
                                                              Inference（導出＝周辺の積み上げ）
                                                                    │ 公開ゲート：合法・出典・確度ラベル
                                                                    ▼
                                                              記者がレンダリング（公開）
```

| 型 | 何か | 不変条件 |
|----|------|----------|
| **Fact** | ソースの実在する一節から抽出した最小の主張 | `source_url`・`raw_excerpt`（原文span）必須。**発明しない**＝INV-R2 の錨 |
| **Claim** | 同じ事象について複数 Fact が支持/矛盾する正規化主張（＝仮説） | 採用可能な支持 Fact が0なら不採用 |
| **Inference** | 複数 Claim を規則で組み合わせ、誰も明言しない結論を導出（C ← A∧B） | 導出チェーン保持・`derived=True`・確度は前提の最弱を超えない |
| **Confidence** | 順序ラベル（未確認/低/中/高/確定）＋計算根拠 | 証拠が許す以上に上げられない |

## 3. 確度の積み上げ（コードが計算する唯一の仕事）

- **独立性**：本数ではなく「何系統」。同一原典の焼き直し（シンジケーション）は `origin` キーで1系統に畳む。
- **信頼度（Admiralty 流）**：チャネル毎の既定グレード A–F を重みへ写像。**法定開示=A** が最上位。
- **矛盾**：独立した信頼できる反証は確度を1段ずつ下げる（隠さず両論保持）。
- **伝播**：導出の確度 = 前提 Claim の確度の**最小**（弱い前提が天井）。決定論＝同じ Fact 群なら必ず同じ結論・同じ確度。

確度の段（`Confidence`）:

| 値 | ラベル | 例 |
|----|--------|----|
| 0 | 未確認 | 単一の弱いソースのみ／裏付けゼロ |
| 1 | 低 | 弱いチャネルが少数 |
| 2 | 中 | 独立2系統が一致（中グレード） |
| 3 | 高 | 法定開示の単独、または独立複数の一致 |
| 4 | 確定 | 法定開示×独立複数が一致 |

## 4. admission / 公開ゲート（既存 compliance の拡張点）

- `admit_fact`：`source_url`・正規チャネル・`raw_excerpt` を欠く Fact を弾く（捏造の温床を断つ）。
- `admit_claim`：採用可能な支持 Fact が無ければ不採用。
- `admit_inference`：`derived=True` 必須・全前提が admissible・チェーンが Fact に解決すること。
- **公開可否**：`confidence >= しきい値（既定=中）` かつ `compliance.py`（NFR-4）通過を要する。
  本 spec は確度・証拠側を担い、権利側は既存 compliance に委譲する。

## 5. タスキング（「どれを掘るか・何を深掘りするか」）

確立された手法（インテリジェンス・サイクル：指示→収集→処理→分析→**配布**）を採用。
チャネル選択は **期待情報価値 × 信頼度 × コスト** で順位付け（決定論）。v0 では信頼度順の
`rank_channels` スタブを置き、後段で価値・コスト項を加える。

## 6. スコープ外（この PR では作らない）

- 実データ収集アダプタ（EDINET/EDGAR 等）— チャネルは型のみ定義
- 記者エージェントの文章生成 — 本基盤を消費する後段
- `run_daily` への接続 — 表示は現状維持

## 7. 不変条件まとめ

- INV-R2：出典なき・原文span なき主張は作らない／載せない。
- 決定論：同じ入力 → 同じ確度・同じ採否（乱数なし・時刻は外から渡す）。
- 単調性：確度は証拠が許す上限を超えない／矛盾で必ず下がる。
- 分離：観測された Fact と導出 Inference を明確に区別し、公開時もラベルで分ける。
