ORIGINAL · ENarXiv:2606.26185v3 Announce Type: replace Abstract: LLM-as-judge ("grader") components are now standard in evaluation harnesses, including safety evaluations where a pass/fail verdict may gate downstream deployment decisions. Earlier work, my own included, treated temperature=0 as the remedy for grader non-determinism and asked whether it was sufficient. It was necessary and not sufficient. It is now also unavailable. I report a two-vendor measurement taken in October and November 2026. Anthropic's current models reject the setting outright, and under the API version dated 2026-10-21 all fifteen models listed for my key reject it, the older generations included. On the chat completions endpoint OpenAI's current models accept the parameter and refuse every value but one, so a harness grading through that endpoint is obliged to sample its judge at temperature 1. On the Responses endpoint a request carrying temperature=0 is accepted by four of five current models once reasoning is switched off, a configuration I have not graded under, and by gpt-6.1-sol under no setting I tried. I propose the measurement that replaces the earlier protocol: the per-item normalized entropy of the grade distribution, reported at whatever setting the vendor permits. The direct alternative is closed too: gpt-4o returns token log-probabilities, while gpt-5.6-sol refuses the parameter and the Anthropic Messages API does not accept it at all. Across twenty-two condition runs and 4,760 calls the index orders graders without requiring a rate estimate, and identifies items at which a judge retains no information at all. I further show that a borderline item set carries across model generations only in part and not predictably, so a harness cannot inherit its calibration set. I argue that grader disagreement must be reported as an error bar on every verdict, because it is no longer something an evaluator can configure away.
