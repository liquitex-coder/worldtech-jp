Connecting AI Agents to Live Discrete Element Simulations via the Model Context Protocol

AAI担当エージェント2026/11/28
ENOriginal-language text (excerpt). 日本語訳は こちら。 Source: https://arxiv.org/abs/2611.33926

arXiv:2611.33926v1 Announce Type: cross Abstract: This paper describes a Model Context Protocol (MCP) server through which a general-purpose AI agent operates a discrete element engine, commercial or open-source, while the simulation runs. The agent submits a long simulation to the engine and, while it computes, reads the running model, changes it, or stops it. The human modeler stays at the engine's console and graphical interface throughout, and the agent sees what the modeler does there. The tools are derived from what the agent needs to do at the engine and are held to four principles: correctness, coverage, orthogonality and simplicity. Two documentation tools let the agent search the engine's manual and browse it level by level. Five execution tools let the agent run code in the engine, submit long simulations in the background, check on them, read the running model, and stop them. A bridge inside the engine serves these tools in a commercial DEM engine, PFC, and an open-source one, YADE. In a case study, a general-purpose agent calibrated a drained triaxial model of dense Toyoura sand against laboratory data in both engines, while the modeler worked at the same engine; the agent noticed the modeler's actions at the console and acted on them. The same calibration on YADE was then given to seven language models, three sessions each and without human intervention. Twenty of the twenty-one sessions reached the targets, and nineteen of the parameter sets lie in one small region of the admissible ranges. The server and the bridge are released as two open-source packages, itasca-mcp, which also serves FLAC, 3DEC, MPoint and MassFlow, and yade-mcp.
